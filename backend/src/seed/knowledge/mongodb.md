# MongoDB

## Document Model

MongoDB is a document database that stores BSON documents (binary JSON with extra types such as ObjectId, Date and Decimal128) in collections. Documents in a collection can have different shapes, though applications usually enforce a schema with Mongoose or JSON Schema validation. The maximum document size is 16 MB.

An ObjectId is a 12-byte identifier containing a timestamp, a random value and a counter, so IDs are roughly sortable by creation time and can be generated by clients without coordination.

## Data Modelling: Embedding vs Referencing

Embed related data when it is accessed together, owned by the parent, and bounded in size — for example interview turns inside an interview session, or addresses inside a user. Embedding gives single-document reads and atomic updates.

Reference other documents (store their ObjectId) when data is shared, large, unbounded or accessed independently — for example sessions reference a user and a resume. References require additional queries or $lookup. Avoid unbounded arrays that grow forever; they hit the size limit and slow updates.

Schema design follows access patterns: model for the queries you run most often. Common patterns: subset (embed recent items, reference the rest), computed (store precomputed aggregates), extended reference (copy a few frequently read fields) and bucket (group time-series data).

## CRUD and Operators

insertOne/insertMany, find/findOne with filters and projections, updateOne/updateMany with update operators, deleteOne/deleteMany. Query operators: $eq, $ne, $gt, $gte, $lt, $lte, $in, $nin, $and, $or, $exists, $regex, $elemMatch. Update operators: $set, $unset, $inc, $push, $pull, $addToSet. Upserts insert when no document matches.

## Indexes

Without an index MongoDB performs a collection scan. Indexes are B-tree based. Types: single field, compound, multikey (on arrays), text, geospatial, hashed (for sharding), TTL (automatically delete documents after a time) and unique indexes. Compound index order matters — follow the ESR guideline: Equality fields first, then Sort fields, then Range fields. For example, an index on { user: 1, createdAt: -1 } serves "latest sessions of a user". Use explain("executionStats") to compare documents examined with documents returned.

## Aggregation Pipeline

The aggregation pipeline transforms documents through stages: $match (filter; place early to use indexes), $project/$addFields (reshape), $group (aggregate with $sum, $avg, $max, $push), $sort, $limit, $skip, $unwind (flatten arrays), $lookup (left outer join with another collection) and $facet (multiple sub-pipelines at once). Dashboards commonly use $match on user then $group to compute counts and averages.

## Transactions and Consistency

Single-document operations are atomic. Multi-document ACID transactions are supported on replica sets and sharded clusters but add overhead; good schema design minimises their need. Write concern controls acknowledgement (w: 1, w: "majority"); read concern controls isolation of reads ("local", "majority", "snapshot"). Read preference routes reads to primaries or secondaries.

## Replication and Sharding

A replica set has one primary accepting writes and secondaries replicating the oplog. If the primary fails, members elect a new primary automatically, providing high availability. Sharding distributes data across shards by a shard key; mongos routers direct queries. A good shard key has high cardinality, even distribution and supports common queries; monotonically increasing keys (like timestamps) create hotspots unless hashed.

## Mongoose

Mongoose is an ODM for Node.js that adds schemas, validation, defaults, middleware (pre/post hooks, e.g. hashing a password before save), virtuals, population of references (populate) and query helpers. select: false on a field (like a password hash) excludes it from queries by default. lean() returns plain objects for faster read-only queries. Enable strictQuery to ignore unknown filter fields.

## Security

Enable authentication and role-based access control, never expose MongoDB directly to the internet, use TLS, and store connection strings in environment variables. NoSQL injection happens when user-supplied objects reach query filters, e.g. a login body {"email": {"$ne": null}} matching any user. Defend by validating types (require strings), casting input, stripping keys starting with $ or containing dots, and using sanitisation middleware.

## When to Use MongoDB

Good fits: flexible or evolving schemas, hierarchical data read as a whole, rapid iteration, and horizontal scaling needs. Less ideal: heavily relational data with many-to-many joins and complex multi-entity transactions, where a relational database is simpler.
